## Exact Gaps To Close Before Claiming Conformance

- Local byte-exact canonicalization now has Somatic-owned vectors and Phase 4G.3 Locus-certified Somatic-origin shared fixtures, but Locus-origin companion fixtures and broader shared edge vectors still need mutual certification.
- Locus and Somatic need broader Ed25519 signing vectors generated by each side and verified by the other.
- Locus and Somatic need shared keyring, expired keyring, under-threshold keyring, wrong-key signature, revoked-key, and namespace-mismatch vectors.
- Somatic pack validation must align optional dependencies, description length, `infohashV2`, future major policy, and transport edge cases.
- Catalog signature generation and verification need Locus-owned shared vectors and a clear high-level Locus verifier boundary.
- License gates need exact result-shape and edge-case parity for publish, seed, catalog, and install.
- Path confinement needs explicit separation between manifest syntax checks and future filesystem staging/install checks.
- Any copied fixtures need source path, commit, digest, and license basis documented.

## Recommended Phase 4G Follow-Ups

1. Add Locus-owned companion shared fixtures and Somatic-side verification.
2. Add Locus-owned signed catalog fixtures or a Locus-side high-level catalog threshold verifier.
3. Align pack/catalog validation edge cases with Locus and the normative spec, including optional dependencies, description limits, future major policy, and `infohashV2`.
4. Add revoked-key, duplicate-signature, wrong-namespace, namespace-mismatch, and boundary timestamp vectors for keyring and publisher verification.
5. Add catalog conflict vectors and exact license policy parity tests.
6. Defer BitTorrent, download, install, quarantine, HTTP/WS catalog serving, and code execution to later explicitly scoped runtime phases.
